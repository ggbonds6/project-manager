# ai-service → ai-backend 迁移方案与对照表

> 目标：把 AI 能力服务从 Python（FastAPI）**全量迁移为 Java**（Spring Boot 3.3.5 / Java 17），
> 与主系统同栈、**独立构建与部署**（默认 8100）。
> 原则：**行为对齐优先于代码美观**——Python 版里每条"踩坑结论"都是真实调试出来的，
> 迁移时必须把结论保留（注释 + 测试），而不是"顺手重写得更优雅"。

## 0. 为什么迁、为什么不合并进主系统

- **迁**：一套工具链、一套发布脚本、一套人；Python 侧只剩"过渡件"（本地向量缓存、单页调试前端）没有长期维护价值。
- **不合并**：平台 OCR / 大模型 / 向量化都在 GPU 机上，AI 能力无论如何都要独立部署、独立发版；
  合并进主系统只会把"AI 发版"绑死"业务发版"。

## 1. 模块对照表

| --- | --- | --- |

## 2. 必须原样保留的"踩坑结论"（Python 注释里的实测结果）

1. **平台 OCR 响应**：批量请求的 `blocks` 在 `results[i]` 里，**不在顶层**；单张才在顶层。
2. **平台不返回置信度**：`confidence` 必须是 `null`，**不许编一个出来**；`low_confidence_pages` 恒空。
3. **渲染参数**：发给平台 150 DPI / JPEG / q85；实测 120~300 DPI 识别结果一致，但体积差 17 倍。
4. **印章默认关**：开启会让吞吐减半，且低 DPI 下会**编造**印章文字（实测读出过完全不相干的银行名）。
5. **Embedding 不支持 MRL 降维**：传 `dimensions` 会 HTTP 400（`does not support matryoshka representation`），
   故默认不传（4096 维）——手册写的 64~4096 与**实际部署**不符，以部署为准。
6. **Rerank 返回的是入参下标**：上游按原顺序返回 `results`，不能把返回顺序当排名。
7. **`calculate` 只放行 `+ - * / ( )`**：`**` / `//` / `%` 已移除（`9**9**9` 能把 CPU 打满）；
   全程 `BigDecimal`（金额精度），返回字符串避免 JSON 浮点丢分位。
8. **思维链默认关**：开启后思考会吃光 `max_tokens`、最终 `content` 为空。
9. **system 消息只允许一条且在首位**（该推理服务遇第二条 system 直接 400）。
10. **大模型/OCR/向量化共用同一网关与同一把 sk**。

## 3. HTTP 契约（逐字段对齐 Python 版）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health?with_llm=&with_ocr=&with_vec=` | `{code,service,version,config,provider,ocr?,llm?,vec?}` |
| POST | `/analyze` (multipart: file, instruction, dpi) | 抽取：`{code,data:{markdown,doc,llm,truncated,warning}}` |
| POST | `/ocr/pdf-info` (multipart: file) | `{code,data:{file,pages,text_chars,chars_per_page,kind,error}}` |
| POST | `/ocr/file` (multipart: file, dpi, force_ocr) | 只识别不调模型：`{code,data:{kind,pages,text,engine,dpi,image_format,elapsed,failed_pages,notes}}` |
| POST | `/documents` (multipart: file, dpi) | 解析入库，返回文档元信息 |
| GET | `/documents` / `/documents/{id}` / DELETE `/documents/{id}` | 文档库 |
| POST | `/upload-tasks` (multipart: file, dpi) | 建上传任务（立即返回，后台解析） |
| GET | `/upload-tasks` / `/upload-tasks/{id}` / DELETE `/upload-tasks/{id}?remove=` | 任务列表/详情/取消或移除 |
| POST | `/chat` (JSON: question, doc_ids, history) | 问答：`{code,data:{answer,trace,rounds,prompt_tokens,completion_tokens,elapsed}}` |

**字段名与层级一律以 `ai-service/src/pm_ai/api.py` 为准**（主系统/前端按老契约读，换语言不该让调用方改代码）。

## 4. 不迁移的东西（清理项）

| 不迁 | 理由 |
| --- | --- |
| 本地 OCR（`ocr_engine.py` / RapidOCR / PaddleOCR / `selfcheck_ocr.py`） | 已于 2026-09-18 移除（质量远逊平台）；Java 版不再引入 |
| `static/index.html` + `marked.min.js`（811 行单页调试前端） | 调试页；正式入口并入主系统前端（复用 antd + `UploadTaskCenter` + `react-markdown`） |
| `scripts/{ocr_try,batch_ocr,inventory,make_samples,analyze_cli}.py` | 一次性摸底/调试脚本，能力已由 `/ocr/file`、`/analyze`、`vec_try` 覆盖；需要批量时用 HTTP 接口写脚本 |
| 本地向量缓存 | 过渡件；OpenSearch 上线后由索引承担（缓存目录仍需保留，作为 local 后端实现） |

# 入库 + 检索

### 迁移过程中新增的三条环境结论（都属于"看起来像缺类、其实是配置"）

1. **Lombok 注解处理器必须显式声明** `annotationProcessorPaths`。不配的话 javac 不做注解处理，
   `@Getter`/`@Slf4j` 全部失效，报一大片"找不到符号 getWorkDir()/getVec()/log"——极易误判成"类没写全"。
2. **`@Async` 在类内自调用时不生效**（走不到 Spring 代理）。上传任务改成显式注入线程池提交，
   否则"后台解析"会静默变同步、接口又回到超时。
3. **`.env` 需要 `spring.config.import: optional:file:./.env[.properties]`** 才等价于 Python 的 dotenv；
   否则运维按老习惯把 sk 放 `.env` 会得到"网关 401 missing api key"，而配置看起来"已经填了"。

### 已知偏差（有意保留，均为可接受）

- `DocumentReader` 的失败页提示文案比 Python 原文多一句"本地 OCR 兜底已移除"（更清楚，不影响契约）。
- `notes` / `dpi` 字段：文本型 PDF 的 `dpi` 为 `null`（与 Python 一致）；Java 侧已改为 `Integer` 以支持该契约。
- `OpenSearchIndex` 只做到"守卫 + 适配层就绪"，检索仍走 local 路径——集群部署后按 §5 的 4 步验证再切换。
