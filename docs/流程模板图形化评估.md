# 流程模板图形化评估（系统管理-流程模板开放 + 拖拽编排）

> 状态：**仅评估，未实施**（v1.8 起记录）。目标：① 开放"固定 HW/SW 两套模板"为可自由定义；② 用流程图拖拽节点组成流程，支持**并列（并行）与分支**，拖完保存即生效。

## 1. 现状

- `phase_template` 表 = 按 `project_type`（HW/SW）的两条**线性有序**模板（sort_no + weight + pay_node + attach_type_hints）。
- 项目创建时按模板顺序生成 `project_phase` 阶段实例；推进、整体进度、阶段漏斗、逾期均建立在**线性推进**之上（设计稿 §9 口径）。

## 2. 目标能力（用户期望）

1. 模板可增删改/复制，形成多套自定义流程（如按局办、按项目大小）；
2. 画布拖拽节点连线，支持：顺序链、**并行（并列节点）**、**分支（排他选择）**；
3. 拖动完成后保存模板，新建项目按图生成阶段。

## 3. 影响面评估（为什么"不能只做前端"）

| 模块 | 线性模型 | 引入并行/分支后的影响 |
| --- | --- | --- |
| 阶段生成 | 顺序 INSERT | 需按图导出拓扑序；并行组如何落库（组标记？） |
| 当前阶段判定 | 第一个进行中/未完成 | 并行时"多条进行中"，容器/列表取谁？需并行组语义 |
| 整体进度 | Σ权重×完成度 | 并行组权重分摊、分支权重分配 |
| 阶段漏斗/统计 | 按当前阶段计数 | 并行会一项目计多条；分支按已选路计 |
| 推进交互 | 线性"下一个"提示 | 并行组要批量推进、分支要选路/跳过 |

结论：这是**数据模型 + 推进语义 + 统计口径**的整体升级，不只是加一个画布。

## 4. 开源方案选型对比

| 方案 | 优点 | 顾虑 | 适合度 |
| --- | --- | --- | --- |
| **AntV X6** | 中文文档/社区成熟；节点、连线、锚点、守卫边、JSON 序列化现成；Vite 集成示例多 | 通用图引擎，BPMN 语义需自建节点面板与校验 | ⭐ 推荐（自建"阶段节点/并行组/分支"面板） |
| **React Flow（@xyflow/react）** | 上手最快、交互流畅、类型好 | 与 X6 同属通用图，需自封装语义 | 适合快速原型 |
| **LogicFlow** | 面向流程图/审批链，自带节点/边面板与"流程引擎"思路，中文友好 | 生态与样式定制要投入 | 次选（如偏向审批流） |
| **bpmn-js（BPMN）** | 标准 BPMN 语义完整（网关即并行/排他分支），规范 | 建模器 UI 偏专业、定制成本高，学习曲线陡 | 仅当需要"标准 BPMN + 将来接流程引擎" |

**推荐组合**：前端建模用 **AntV X6（或 LogicFlow）**，模板图以 JSON/两表（node/edge）持久化；生成项目阶段时做**拓扑排序 + 并行组标记**。

## 5. 分期落地建议（不实施，仅供排期）

- **A 期（低成本，可先行）**：开放模板 CRUD——新增/复制/启用 HW/SW 之外的任意模板，支持自定义"有序阶段列表"（增删改、排序、权重、付款节点、附件提示）。不改推进与统计。
- **B 期**：引入 X6 画布，把"线性模板"可视化编辑（拖节点成链 + 自动校验环路），仍按顺序推进，可灰度发布。
- **C 期**：正式支持**并行/分支**：
  1. 模板数据模型升级（线性序列 → 有向图 + 并行组/分支语义）；
  2. 明确推进语义：并行组默认"全部完成才通过/任一完成可先过"需业务拍板；分支"条件选择其一（记录选择原因）"；
  3. 重定义当前阶段、整体进度、阶段漏斗、逾期口径；
  4. 兼容存量线性数据（视为无并行/分支的特殊图）。

## 6. 结论

- 技术上完全可行，主流选 **AntV X6 / LogicFlow + 自有模板模型**；
- 但**并行/分支会牵动推进、进度、统计全链路语义**，建议按 A→B→C 分期、先开放线性自定义模板验证需求，再上图形化与分支；
- 当前**不实施**，等待业务确认：并行组通过规则（全部/任一）、分支选择方式等口径后进入 A 期排期。
