### 2.1 连接方式（官方文档核实的驱动级能力，无需 VIP/中间件）

```text
jdbc:yasdb:primary://主IP:1688,备IP:1688/project_manager?poolTimeout=60&failover=on&failoverType=session&failoverMethod=basic&failoverRetries=5&failoverDelay=2
```

- `serverType=primary`：驱动按序连接并执行 `SELECT * FROM DATABASE_ROLE` 判断角色，**只保留主节点连接** → 地址顺序写错也不会有写备风险（仍建议主在前）。
- `failover=on`（TAF 开启）：主库故障后自动重连新主，应用**无需重启**。
- `failoverType=session`：断线自动重连并重置语句句柄（select 档限制多，不用）。
- 心跳（默认开）更快发现死连接；`poolTimeout` 建议显式调小（默认 300s）。
- ⚠️ **边界**：TAF 只对"连接断开后重连"透明；**执行中的事务在主库故障时会失败回滚**。→ 关键写操作建议 Service 层 Spring Retry（2~3 次），前端提交失败给重试提示。
- ✅ **备库 IP 已确认**：备库为 **10.254.212.107:1688**（原 106 为笔误，已修正）。

### 2.2 账号

- 用户提供：`sys`（DBA 账号，密码**不写入仓库文档**，仅经环境变量/现场注入）。应用直连请用**环境变量注入**，勿提交明文到 Git（密码含 `@`，YAML 必须加引号）。

### 4.4 主键 IDENTITY：可行性结论与落地

**可行性确认（用户第 6 点）**：
1. **Oracle 可行**：IDENTITY 列是 Oracle **12c 正式引入**的标准特性（`GENERATED [ALWAYS | BY DEFAULT [ON NULL]] AS IDENTITY`），内部基于系统序列（`ISEQ$$_xxx`），用于替代"序列+触发器"的传统自增写法，是现代 Oracle 推荐做法。
2. **崖山声明支持**：官方 CREATE TABLE 文档含 `identity_clause`，语法同 Oracle。→ **用户判断成立**。
3. **但"可行"分两层，最后一层必须 PoC 实测**：
   - DDL 层：Oracle / 崖山均支持 ✓；
   - 驱动层（崖山 JDBC）：MP 的 `IdType.AUTO` 依赖 **`getGeneratedKeys()`** 在 INSERT 后回填主键。崖山驱动是否实现 → **PoC 首验**（§10 第 2 项）。若不通，回退序列方案（`@KeySequence` + `IdType.INPUT`）。

**DDL 写法（固定为 BY DEFAULT，见 §6）**：`id BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL` + `PRIMARY KEY(id)`。
- `BY DEFAULT`（而非 ALWAYS）是**刻意选择**：历史数据迁移需要显式带 id 导入（ALWAYS 会禁止显式插入）。
- **实体代码**：`BaseEntity` 保持 `@TableId(type = IdType.AUTO)` **不动**；`application.yml` 的 `id-type: auto` 保持。

**结论：容易，约 80 行，交给 AI 实现即可。** Flyway 的核心心智模型 = "版本号排序 + 只跑一次 + 版本表"，不需要外部依赖。

### 5.1 目录与脚本规划

```
backend/src/main/resources/db/
├── migration-yashan/          # 新目录：V1~V8 转换后的 yashan 脚本（全量）+ 后续所有增量
│   ├── V1__init_schema.sql    # 内容按 §6 规则改写
│   ├── ...                    # V2~V8
└── migration/                 # 旧 MySQL 方言脚本目录：迁移验证完成后删除
```

### 5.2 runner 设计（供 AI 实现）

```java
@Component
public class YashanMigrationRunner implements ApplicationRunner {
    // 1. CREATE TABLE IF NOT EXISTS schema_version(version VARCHAR(50) PRIMARY KEY, applied_at TIMESTAMP)
    // 2. 扫描 classpath:db/migration-yashan/*.sql，按 "V{n}__" 解析版本并排序
    // 3. 跳过 schema_version 已记录版本
    // 4. 逐文件：读入 → 剔除 "--" 注释 → 按行尾 ";" 拆句（本库 DDL 无 PL/SQL 块，可安全拆分）
    // 5. JdbcTemplate 逐句执行；文件全部成功 → INSERT INTO schema_version
    // 6. 任一句失败 → 回滚本文件并抛出异常，fail-fast 阻止启动
    // 注意：执行顺序必须早于 DataInitializer（用 @Order(1)）
}
```

- 全量首建（新库无历史）：runner 首次启动即按 V1→V8 顺序建全部表 + 种子。
- 与 `DataInitializer`（演示账号）解耦：`@Order` 保证建表先于数据初始化。

## 6. DDL 转换规则（V1~V8 → yashan）

| MySQL 写法 | yashan 写法 | 说明 |
| --- | --- | --- |
| `VARCHAR(n)` | `VARCHAR(n CHAR)` | **必改**；否则按字节，UTF8 中文仅 1/3 容量 |
| `DATETIME` | `TIMESTAMP` | 审计/时间列（Java 端填充，无 DB 默认值负担） |
| `DATE` | `DATE` | 保留（崖山 DATE 含时分秒） |
| `TEXT`（10 处） | `CLOB` | project.content_summary/note/result_fields、project_overview.intro_md/modules_json、phase_tpl.guide/key_materials、stage_guide_materials.guide/key_materials/flow_json |
| `DECIMAL(p,s)` | `NUMBER(p,s)` | 金额列保留精度 |
| `BIGINT ... AUTO_INCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL` | §4.4 |
| `TINYINT / INT / BIGINT / CHAR` | 原样 | 崖山原生支持 |
| `ENGINE=InnoDB DEFAULT CHARSET=... COMMENT='...'`（表尾） | 删除 ENGINE/CHARSET/COLLATE；`COMMENT ON TABLE t IS '...'` | 表注释 |
| 列内联 `COMMENT 'x'` | 拆出 `COMMENT ON COLUMN t.c IS 'x'` | 列注释 |
| 反引号 `` ` `` | 去掉（裸标识符自动转大写） | 与 MP 查询一致 |

### 转换示例（sys_user 节选）

```sql
CREATE TABLE sys_user (
  id            BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  account       VARCHAR(64 CHAR)  NOT NULL,
  name          VARCHAR(64 CHAR)  NOT NULL,
  role          VARCHAR(20 CHAR)  NOT NULL DEFAULT 'MANAGER',
  status        TINYINT           NOT NULL DEFAULT 1,
  deleted       TINYINT           NOT NULL DEFAULT 0,
  create_time   TIMESTAMP         NULL,
  update_time   TIMESTAMP         NULL,
  PRIMARY KEY (id)
);
COMMENT ON TABLE  sys_user     IS '系统用户';
COMMENT ON COLUMN sys_user.account IS '登录账号';
COMMENT ON COLUMN sys_user.name   IS '姓名';
```

## 7. 历史数据迁移

**先决确认**：请用户明确当前 MySQL 库中是否有**需要保留的业务数据**。若仅演示/种子数据（V2 字典 + 手工录入的测试项目），建议**只迁移结构 + 重灌种子**（最简单，零 id 冲突风险）。

若有需保留数据，两种方式评估如下：

| 方式 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| **A. 迁移工具类（推荐）** | 类型/格式/空值处理在 Java 内可控；边读边写可加日志与断点；不依赖 mysqldump 方言差异 | 需写约 200~300 行代码（AI 实现成本低）；大数据量偏慢（本项目数据量小，无碍） | 数据量 < 数十万行 |
| B. SQL 导出（mysqldump） | 简单直接 | 导出的 INSERT 为 MySQL 方言，长文本/日期/空串需清洗；显式 id 与建表顺序需协调 | 纯结构/少量数据 |

**迁移工具类设计要点**：
1. 读 MySQL（只读连接，原驱动暂留一个迁移专用 profile）→ 写崖山，逐表分批（每批 ~500 行）提交。
2. **表间顺序**：先父表后子表（dict_item → phase_template/phase_tpl → project → project_phase/contract → payment/attachment/operate_log/project_overview/stage_guide_materials），保持引用不悬空。
3. **保留原 id**（业务引用、父子关系依赖原值）→ 显式插入 id 列。

### ⚠️ IDENTITY 与历史数据导入的核心坑（必须处理）

Oracle 的 identity 底层是系统序列，**BY DEFAULT 下显式插入 id 不会推进内部计数**——若插入的最大 id（如 120）大于当前计数，后续应用不带 id 插入会撞唯一键。

**处置（写入迁移流程第 3 步，需 PoC 验证崖山支持度）**：数据导入完成后，对每张表校准 identity 起点为 `max(id)+1`，二选一：
1. `ALTER TABLE t MODIFY (id GENERATED BY DEFAULT AS IDENTITY (START WITH N))` —— 若崖山支持（需厂商确认）；
2. 或查询崖山是否提供 identity 计数同步的系统过程/语法（若无，改用**不带 id 的重灌顺序**：先建表 → 工具类只迁非 id 列，让 identity 从头生成——但此法会改变所有引用 id，仅当业务 id 无外部硬编码时才可用）。

> PoC 阶段就测"显式插 id 到 N，再不带 id 插入是否冲突/如何校准"这一场景，**不要等到数据迁移当天才发现**。

### 迁移后校验
- 逐表 count 对比；金额表 `SUM(amount)` 对比；抽样行全字段比对（尤其 CLOB/时间/空串）；应用端跑一遍 §11 回归。

## 12. 风险与回滚

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| getGeneratedKeys 不支持 | 中 | PoC 首验；序列方案兜底（改动小） |
| identity 计数与历史 id 冲突 | 中 | PoC 第 3 项专项验证；§7 处置 |
| TAF 对进行中事务不透明 | 中 | 关键写操作 Spring Retry + 前端提示 |
| Flyway runner 拆分语句误伤 | 低 | 脚本纯 DDL 无 PL/SQL；fail-fast |
| 空串=NULL 语义 | 低 | 回归用例覆盖 |
| 驱动 system scope 打包遗漏 | 低 | §8 H 项断言可执行 jar 启动 |

**回滚策略（MySQL 不保留的语境）**：MySQL 库在切换验证完成前**保持只读保留**作为保险；迁移工具类**幂等可重跑**（以 id/唯一键去重）。全部验证通过后才下线 MySQL。回滚 = 重跑迁移工具类至崖山（数据以最新 MySQL 快照为源），或对崖山做切换前全量备份后恢复。

## 13. 待确认事项（厂商 / 运维 / 用户）

> 2026-09-09 更新：已通过实库 PoC 解决 getGeneratedKeys（✅）、identity 校准语法（✅）、`DATABASE_ROLE` 权限（✅，sys 无额外权限）、驱动 TAF 参数接受（✅）。剩余事项：

3. **字符集与 emoji**：库级字符集默认值待确认；4 字节 emoji 在 UTF8 下是否支持需回归。
4. **连接数/运维参数**：Hikari 池 10 是否合适；复制延迟监控方式待运维。
5. **本地 MySQL 数据去向**：若本地 MySQL（未运行）有需保留业务数据，请提供源库连接，走 §7 迁移工具类；否则仅结构+种子（当前 V2/V5 已含字典/模板种子）。
