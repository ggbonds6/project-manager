## 1. 为什么是崖山 Oracle 模式

**一句话结论**：按信创要求选定崖山 **Oracle 兼容模式（yashan）单一路线**——它兼容本项目用到的全部 SQL 能力，
而代码侧 ORM 化程度很高（**0 个 XML Mapper**、0 存储过程/触发器/视图、**仅 1 处** Java 方言点 + **7 处**手写 SQL），
所以工作量在 **DDL 转换 + 数据迁移 + 回归验证**，不在业务代码。**MySQL 兼容模式方案已彻底关闭**（形态与长期性隐患），
MySQL 8 + Flyway 已下线。

| 关键约束 | 对我们的后果 |
| --- | --- |
| `VARCHAR(n)` 不指定单位时**默认按字节** | 不写 `CHAR` 会把中文容量砍到 1/3 → **P0 风险** |
| 无 `AUTO_INCREMENT` | 主键改 **identity** |
| Flyway 官方支持列表（50+ DBMS）**不含 YashanDB** | 必须自研 runner（§3） |
| **DDL 隐式提交、无回滚** | 迁移脚本中途失败会留中间态，须人工处置（§5） |
| 空字符串按 **NULL** 存储 | 与 MySQL 语义不同，保存/查询需回归 |

## 2. 方言约定（必须遵守的写法）

| MySQL 写法 | 崖山写法 | 说明 |
| --- | --- | --- |
| `VARCHAR(n)` | **`VARCHAR(n CHAR)`** | **必改**；否则按字节，UTF8 下一个汉字 3 字节→`VARCHAR(128)` 仅约 42 个汉字 |
| `TINYINT` / `INT` / `BIGINT` / `CHAR` | 原样 | 崖山原生支持（Oracle 反而不支持 TINYINT/BIGINT） |
| `DATETIME` | `TIMESTAMP` | 审计/时间列（Java 端填充，无 DB 默认值负担） |
| `DATE` | `DATE` | 保留（崖山 DATE 含时分秒，范围 `1-1-1 ~ 9999-12-31`） |
| `TEXT`（10 处） | `CLOB` | project.content_summary/note/result_fields、project_overview.intro_md/modules_json、phase_tpl.guide/key_materials、stage_guide_materials.guide/key_materials/flow_json |
| `DECIMAL(p,s)` | `NUMBER(p,s)` | 金额列保留精度 |
| `BIGINT ... AUTO_INCREMENT` | **`BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL`** | 见下行"identity 三点" |
| 表尾 `ENGINE=InnoDB DEFAULT CHARSET=... COMMENT='...'` | 删除 ENGINE/CHARSET/COLLATE；改用 `COMMENT ON TABLE t IS '...'` | 列内联 `COMMENT 'x'` 同样拆成 `COMMENT ON COLUMN t.c IS 'x'` |
| 反引号 `` ` `` | 去掉（裸标识符自动转大写） | 与 MP 查询一致 |
| `YEAR(x) = n` | `EXTRACT(YEAR FROM x) = n`；**推荐**改 `x >= #{start} AND x < #{end}`（走索引） | 已改 4 处（`ProjectService` ×3 / `StatsService` ×1） |
| `.last("limit 1")` | `.last("FETCH FIRST 1 ROW ONLY")` | 已改 2 处 |
| `CONCAT(...)` | 原样保留 | 崖山内置函数含 `CONCAT`，PoC 已实测通过 |
| 普通 `KEY` 内联、多行 `VALUES`、`UPDATE ... JOIN` | 拆到表外 `CREATE INDEX`（**索引名全局唯一**）、单行 VALUES、改写为等价 UPDATE | 迁移时的统一改写惯例 |

**identity 三点（定死）**

1. **必须用 `BY DEFAULT`，不用 `ALWAYS`** —— 历史数据迁移需要显式带 id 导入（`ALWAYS` 会禁止显式插入）。
2. **实体与配置零改动**：`BaseEntity` 保持 `@TableId(type = IdType.AUTO)`、`application.yml` 的 `id-type: auto` 不变；
   `getGeneratedKeys` 回填**已实测成功**（PoC），故不需要序列 + `@KeySequence` 那一套。
3. **迁移/大批量显式插 id 后必须校准起始值**（否则新增会撞唯一键，见 §5）。

## 3. 迁移执行方式（自研 `YashanMigrationRunner` 替代 Flyway）

- **实现位置**：`backend/src/main/java/com/pmgt/common/config/YashanMigrationRunner.java`（`@Component` + `@Order(1)`，`ApplicationRunner`）。
  心智模型 = Flyway 那套「**版本号排序 + 只跑一次 + 版本表**」，无外部依赖；`@Order(1)` 保证**建表先于 `DataInitializer`**。
- **行为**：建版本表 `schema_version(version VARCHAR(100) PK, applied_at TIMESTAMP)`（先查 `user_tables` 再建）→
  扫描 `classpath*:db/migration-yashan/*.sql`，按文件名 `V{n}__` **数值排序** → 跳过 `schema_version` 已登记的**文件名**（幂等）→
  剔除整行 `--` 注释、按**行尾分号**切句、逐句 `JdbcTemplate.execute`（执行时去掉语句尾分号，崖山 JDBC 不接受）→
  文件全部成功才登记；**任一句失败立即抛异常阻止启动（fail-fast）**。
- **脚本目录与当前版本**：`backend/src/main/resources/db/migration-yashan/`，当前 **V1~V13**（V13 为 v3.6.0 的 AI 集成表）。

| 版本 | 内容 | 版本 | 内容 |
| --- | --- | --- | --- |
| V1 | 初始建表（9 表，含已删的 `sys_dept`） | V7 | `phase_tpl` |
| V2 | 种子数据 | V8 | `stage_guide_materials` |
| V3 | `DROP TABLE sys_dept` | V9 | `attachment_upload_task`（后台上传记录） |
| V4 | 子项目 + `contract` | V10 | 合同字段扩充 + `project_division` |
| V5 | 文件类型字典 | V11 | 付款过程字段 + 合同附件归位 |
| V6 | `project_overview` | V12 | `project_contract`（项目↔合同多对多） |

> 旧 `db/migration/`（MySQL 方言）**已删**（git 历史保留）；全库 `mysql|3306|flyway` 断言零命中。**当前共 14 张表。**

**新增一个迁移脚本怎么做**

1. 在 `db/migration-yashan/` 新建 **`V{n}__desc.sql`**（`n` = 现有最大版本 +1，当前下一个是 **V13**；`desc` 用下划线小写）；
2. 语句一律按 §2 方言写：`VARCHAR(n CHAR)`、`CLOB`、`TIMESTAMP`、`NUMBER`、identity 主键，注释用 `COMMENT ON`；
3. **一条语句以行尾 `;` 结束**，值与注释里**不要出现分号**，不要写 PL/SQL 块（runner 不会解析块）；
4. **纯 DDL 无事务**：先在本地/测试库空跑一次；建索引/约束前先确认**是否已存在**（V1 已有 11 个索引，重复建报 `YAS-02043`）；
5. 提交后在应用启动日志里确认 `[yashan-migration] 完成并登记: V13__...`；镜像里已 `COPY` 该目录，随发布生效，**无需手工执行工具**；
6. ⚠️ **已发布脚本不要改名或改内容**（登记以文件名为准，改名会被当新脚本重跑）。

## 4. 连接与高可用

| 项 | 值 / 做法 |
| --- | --- |
| 主备地址 | 主 `10.254.212.106:1688`、备 `10.254.212.107:1688`（地址顺序建议主在前） |
| 库名 / schema | **`PM`**（Oracle 模式下即 schema 名，**必须大写**；写 `project_manager` 会连错库） |
| 应用账号 | **业务账号 `pm`**（CONNECT/RESOURCE）。⚠️ **勿用 `sys`**：按登录用户 schema 查表会报 `YAS-02012`；密码不符 + 容器反复重试会触发账号锁定 `YAS-02193` |
| 口令 | **一律 `YASHAN_PASSWORD` 环境变量注入，不落仓库/镜像**（口令含 `@` 等字符，YAML 里必须整体加引号） |
| 驱动 | `yashandb-jdbc-1.9.3.jar`，**无 Maven 坐标 → 本地 `backend/lib/` + `system` scope**，并需 `spring-boot-maven-plugin` 开 `includeSystemScope`（否则不打进可执行 jar）。私服就绪后可改普通依赖 |
| 连接 URL | `jdbc:yasdb:primary://${YASHAN_MASTER_IP}:1688,${YASHAN_STANDBY_IP}:1688/${YASHAN_DB}?poolTimeout=60&failover=on&failoverType=session&failoverMethod=basic&failoverRetries=5&failoverDelay=2` |
| 分页方言 | `MybatisPlusConfig`：`new PaginationInnerInterceptor(DbType.ORACLE)`——**不能靠自动识别**（MP 源码把 YASDB 归入 `mysqlSameType`） |
| 连接池 | Hikari `maximum-pool-size: 10` / `minimum-idle: 2` / `connection-timeout: 15000`（主备切换留足建连时间） |
| 高可用机制 | 驱动级 **primary + TAF**：`serverType=primary` 时驱动按序连接并查 `DATABASE_ROLE` 只保留主节点（写不到备库）；主库故障自动重连新主，**应用无需重启** |
| ⚠️ TAF 边界 | 只对「连接断开后重连」透明；**执行中的事务在主库故障时会失败回滚** → 关键写操作 Service 层 `Spring Retry` 2~3 次，前端给重试提示（kill 主演练仍属待办） |

## 5. 踩坑清单（会再踩的）

| # | 坑 | 处置 |
| --- | --- | --- |
| 1 | **identity 起始值不随显式插 id 推进**（`BY DEFAULT` 下插到 2000，下一条不带 id 仍得 1） | 迁移后**每表校准**：`ALTER TABLE t MODIFY (id GENERATED BY DEFAULT AS IDENTITY (START WITH max(id)+1))` ——**实测生效** |
| 2 | `VARCHAR(n)` 不写 `CHAR` → 中文截断（`VARCHAR(128)` 只存约 42 汉字） | 所有 `VARCHAR` 一律带 `CHAR`；本项目最大 500，未触到「超 8000 字节自动转 LOB」的边界 |
| 3 | `YEAR()` 不存在 | 改 `EXTRACT(YEAR FROM ...)`，或范围比较（推荐，走索引） |
| 4 | `limit 1` | 改 `FETCH FIRST 1 ROW ONLY` |
| 5 | **崖山 DDL 隐式提交、无回滚** | 脚本一条条确认；中途失败会「已执行但未登记」。正确处置：`docker compose stop` 止血 → 手工回滚已执行语句 → 重跑（容器 `restart: unless-stopped` 会自动重试并撞 `duplicate column`） |
| 6 | 重复建索引/列 | v3.5.0 的 V11 首跑就失败在最后一行 `CREATE INDEX`（该索引 V1 已建，报 `YAS-02043`）→ 新脚本先查存在性 |
| 7 | 驱动 **system scope 默认不进可执行 jar** | 必须 `includeSystemScope`，并用 `java -jar` 实跑验证驱动加载 |
| 8 | 空串按 **NULL** 存储 | 保存/查询语义回归（表单空串、`= ''` 条件） |
| 9 | CLOB 读写 | `setString` 即可，**2 万汉字往返一致**；迁移后按表抽样比对 CLOB/时间/金额（金额另做 `SUM(amount)` 双端比对） |
| 10 | 字符集/emoji | 库级字符集默认值、4 字节 emoji 是否支持**仍未确认**（原分析建议若文件名可能含 emoji 需向厂商确认 `UTF8MB4`），回归时覆盖 |
| 11 | 别再把 Flyway / `db/migration/` 引回来 | Flyway 官方不支持崖山；旧 MySQL 方言目录已删，新脚本一律进 `db/migration-yashan/` |
