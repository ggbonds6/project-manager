> 运行架构、OBS 原理、网关、运维细节以《双机ARM服务器独立部署方案.md》为准（本文不重复原理）。

## 0. 五分钟看懂（先读这一段）

### 0.1 角色与机器

| 角色            | 机器                         | 架构          | 外网  | 需要装什么                                            |
| ------------- | -------------------------- | ----------- | --- | ------------------------------------------------ |
| **开发机 / 构建机** | 你的 Windows 电脑              | x86_64      | ✅ 有 | Git、Docker Desktop（见 §1.1）；**唯一能联网构建的机器，源码只在这里** |
| **服务器 A**     | `pdmsappgh`（银河麒麟 V11）      | **aarch64** | ❌ 无 | Docker daemon + compose v2（见 §1.2）               |
| **服务器 B**     | `ai-kingbase-gh`（银河麒麟 V11） | **aarch64** | ❌ 无 | 同上                                               |

- 登录用户两台均为 **`lhim`**；工作目录两台均为 **`/home/lhim/pm`**。
- 两台都是 **aarch64** → **只产一份 arm64 镜像，两台通用**（各机仍可用 `uname -m` 复核）。
- **服务器不联网** → 所有构建在开发机完成；服务器只做 `docker load` + `docker compose up -d`，**绝不加 `--build`**。
- **服务器上不放源码**：镜像已包含后端 jar（含建库迁移 SQL）、前端产物、nginx 配置；服务器运行目录里只有 `docker-compose.yml` + `.env` 两个文件（已实测：仅这两个文件即可跑通整套系统）。

### 0.2 两条路径（对号入座）

| 我要做什么              | 走哪几节              | 频率   |
| ------------------ | ----------------- | ---- |
| 第一次把系统装到服务器上       | §1 → §2 → §3 → §5 | 每台一次 |
| 改了代码，发新版本到服务器      | §2 → §4 → §5      | 每次发版 |
| 只想在本机用 Docker 试跑一下 | §1.3              | 按需   |

流程总览：

```text
【开发机】改代码 → 本地自测 → §2.2 一键打包(make-release.sh，出「镜像包 + compose + .env模板」)
                                                        │
                                                  §2.4 scp 上传
                                                        ▼
【服务器】§3 首次部署 / §4 迭代更新：docker load → docker compose up -d → §5 验收
          （服务器无源码；日常只需改 .env 里的 IMAGE_TAG）
```

### 0.3 目录与文件约定（**最容易搞错，先记住**）

**服务器侧**（`/home/lhim/pm/` 下只有这两个目录，**没有源码**）：

| 内容       | 路径（服务器上）                  | 说明                                                 |
| -------- | ------------------------- | -------------------------------------------------- |
| **运行目录** | `/home/lhim/pm/app/`      | ★ 部署只认这里，里面只有 2 个文件：`docker-compose.yml` + `.env`  |
| 镜像包归档    | `/home/lhim/pm/releases/` | 每次发版往这里丢 `pm-images-aarch64-<版本>.tar.gz`（归档，不参与运行） |

```text
/home/lhim/pm/
├─ releases/                    ← 镜像包归档（可只留最近 2~3 个版本）
│   └─ pm-images-aarch64-v3.1.1.tar.gz
└─ app/                         ← 运行目录：docker 相关，全部内容
    ├─ docker-compose.yml       ← 服务器专用编排（无 build 段）
    └─ .env                     ← 现场维护；⚠️ 必须与 compose 同目录（compose v2 只从 compose 文件所在目录读 .env）
```

**开发机侧**：

| 内容     | 路径                                        | 说明                                                |
| ------ | ----------------------------------------- | ------------------------------------------------- |
| 源码与构建  | 仓库根目录                                     | **只有开发机存源码**                                      |
| 开发用编排  | `deploy/docker/docker-compose.yml`        | 含 `build:` 段，供本机 `--build` 用（服务器**不要**用这个文件）      |
| 服务器用编排 | `deploy/docker/docker-compose.deploy.yml` | 无 `build:` 段，运行目录无需源码（打包时改名 `docker-compose.yml`） |
| 发布产物   | `dist/pm-release-<版本>/`                   | 已在 `.gitignore`，不入库                               |

## 1. 一次性准备（只做一次）

### 1.1 开发机（Windows）准备

**① 安装 Docker Desktop**

1. 下载：<https://www.docker.com/products/docker-desktop/>（Windows 版）。
2. 安装时选 **WSL2 后端**（需 Windows 10/11 已启用 WSL2，向导会引导）。
3. 启动 Docker Desktop，等右下角显示 **Engine running**。

验证（PowerShell 或 Git Bash 均可）：

```bash
docker --version          # 期望 Docker version 24+ / 26+
docker compose version    # 期望 Docker Compose version v2.x
docker buildx version     # 期望 github.com/docker/buildx v0.x
docker run --rm hello-world   # 期望打印 Hello from Docker!
```

**② 启用 ARM64 模拟（本机是 x86；只需执行一次）**

```bash
docker run --privileged --rm tonistiigi/binfmt --install arm64
docker buildx ls          # 列表里应出现 linux/arm64
```

**③ 拿到源码**

```bash
# 已有仓库则直接更新
cd <你的仓库目录>/project-manager && git pull
# 没有则克隆
git clone https://github.com/ggbonds6/project-manager.git && cd project-manager
```

> 国内网络拉镜像慢：Docker Desktop → Settings → Docker Engine 配置 registry mirror（阿里云/中科大等）。


### 1.2 服务器准备（**A、B 每台各执行一次**）

登录方式：`ssh lhim@pdmsappgh` / `ssh lhim@ai-kingbase-gh`。

```bash
# ① 启动 Docker daemon 并设开机自启
sudo systemctl enable --now docker
systemctl status docker --no-pager | head -5     # 期望：Active: active (running)

# ② 把 lhim 加入 docker 组（免 sudo）
sudo usermod -aG docker lhim
# —— 执行完后【退出 SSH 重新登录】再验证 ——
docker ps                                        # 期望：能输出表头 CONTAINER ID ...（哪怕没有容器）
```

```bash
# ③ 安装 docker compose v2 插件（麒麟源无此包，用官方 aarch64 二进制）
uname -m                                         # 确认是 aarch64

# 在【有网的开发机】下载后传过去：
#   curl -L -o docker-compose-linux-aarch64 \
#     https://github.com/docker/compose/releases/latest/download/docker-compose-linux-aarch64
#   scp docker-compose-linux-aarch64 lhim@pdmsappgh:/tmp/

mkdir -p ~/.docker/cli-plugins
cp /tmp/docker-compose-linux-aarch64 ~/.docker/cli-plugins/docker-compose
chmod +x ~/.docker/cli-plugins/docker-compose
docker compose version                           # 期望：Docker Compose version v2.x
```

```bash
# ④ 建两个目录（运行目录 + 镜像归档；无源码）
mkdir -p /home/lhim/pm/app /home/lhim/pm/releases
```

**自检**：以下三条全部通过，环境才算就绪。

```bash
uname -m                  # aarch64
docker ps                 # 不报权限错误
docker compose version    # 有 v2.x 版本号
```

### 1.3 （可选）开发机用 Docker 试跑

仅用于本机验证，**用本地存储、端口 8088**，不要用生产 `.env`：

```bash
cd project-manager/deploy/docker
cp .env.example .env      # 然后编辑 .env：
#   IMAGE_TAG=latest
#   YASHAN_DB=PM / YASHAN_USER=pm / YASHAN_PASSWORD=<密码>

# 用完清理：docker compose -f deploy/docker/docker-compose.yml down
```

## 2. 发版：开发机操作（每次发版都做一遍）

### 2.1 本地开发与自测

1. 改代码 → 本地跑通：后端 `mvn spring-boot:run`，前端 `npm run dev`。
2. 打版本标签（约定见 §7）：`git tag v3.1.1`。
3. **提交但不推送**（推送由你决定；部署不依赖远端）。
4. 需要时把变更记入 `ITERATION.md`。

### 2.2 一键打包（推荐）

**在开发机、仓库根目录执行**：

```bash
bash scripts/make-release.sh v3.1.1
```

| 项    | 说明                                                               |
| ---- | ---------------------------------------------------------------- |
| 参数   | `<版本>`（必填，与 `IMAGE_TAG` 一致，如 `v3.1.1`）；可选第二参数平台，默认 `linux/arm64` |
| 耗时   | 首次 10~~30 分钟（QEMU 模拟 + 拉依赖），有缓存后 1~~3 分钟                         |
| 预期输出 | 末尾打印 `✅ 发布目录已生成: dist/pm-release-v3.1.1/` 并列出文件                  |

产出目录 `dist/pm-release-<版本>/`：

```text
pm-images-aarch64-v3.1.1.tar.gz     ← 镜像包（约 150MB），两台服务器通用
docker-compose.yml                  ← 服务器专用编排（无 build 段，运行目录靠它 + .env）
.env.example                        ← 配置模板（IMAGE_TAG 已预填本次版本）
pm-upgrade.sh                       ← 服务器升级脚本（可选）
服务器部署步骤.txt                    ← 服务器端照做即可
```

> 本机已存在同版本镜像、只想重打包时：`SKIP_BUILD=1 bash scripts/make-release.sh v3.1.1`。

### 2.3 手工打包（等价步骤，排障时用）

```bash
cd project-manager
VER=v3.1.1
mkdir -p dist

# 注意 --load：不加则镜像只留在 buildx 缓存里，下一步 docker save 会报找不到镜像
docker buildx build --platform linux/arm64 --load -t pm-backend:${VER}  -f deploy/docker/Dockerfile.backend  .
docker buildx build --platform linux/arm64 --load -t pm-frontend:${VER} -f deploy/docker/Dockerfile.frontend .

docker save pm-backend:${VER} pm-frontend:${VER} | gzip > dist/pm-images-aarch64-${VER}.tar.gz
ls -lh dist/pm-images-aarch64-${VER}.tar.gz      # 期望：~150MB
```

### 2.4 上传到两台服务器

**在开发机执行**（开发机需能访问服务器内网）。**只传 3 个文件，不传源码**：

```bash
VER=v3.1.1
R=dist/pm-release-${VER}

# 1) 镜像包 → releases 目录（两台）
scp ${R}/pm-images-aarch64-${VER}.tar.gz lhim@pdmsappgh:/home/lhim/pm/releases/
scp ${R}/pm-images-aarch64-${VER}.tar.gz lhim@ai-kingbase-gh:/home/lhim/pm/releases/

# 2) 编排文件 + .env 模板 → 运行目录 app（两台）
ssh lhim@pdmsappgh 'mkdir -p /home/lhim/pm/app'
ssh lhim@ai-kingbase-gh 'mkdir -p /home/lhim/pm/app'
scp ${R}/docker-compose.yml ${R}/.env.example lhim@pdmsappgh:/home/lhim/pm/app/
scp ${R}/docker-compose.yml ${R}/.env.example lhim@ai-kingbase-gh:/home/lhim/pm/app/
```

> **`.env` 永远不上传、不覆盖**：它只存在于服务器本地（§3 第 2 步现场生成），生产值为 OBS + 8080，与本机测试值不同。  
> 源码改了**不需要**传源码——改动已通过镜像带过去；只有当你需要在服务器上排查源码时才另说。

## 3. 服务器：首次部署（**每台各做一遍**，逐步照做）

> 前提：§1.2 服务器环境自检三条全部通过；镜像包与两个部署文件已按 §2.4 上传。

**第 1 步 · 确认运行目录**（服务器执行）

```bash
cd /home/lhim/pm/app
ls -l          # 期望看到：docker-compose.yml、.env.example
```

**第 2 步 · 配置 `.env`**（⚠️ 关键：必须与 docker-compose.yml 同目录，即就在这个 `app/` 下）

```bash
cd /home/lhim/pm/app
cp .env.example .env
vi .env
```

按下面逐项填写（**两台服务器内容必须完全一致**；`<...>` 为需你填写的值）：

```ini
# ---- 镜像版本：必须与 docker load 进来的 tag 一致 ----
IMAGE_TAG=v3.1.1

# ---- 崖山数据库（Oracle 模式，schema 即库名） ----
YASHAN_MASTER_IP=10.254.212.106
YASHAN_STANDBY_IP=10.254.212.107
YASHAN_DB=PM                 # 崖山 Oracle 模式下的 schema 名（生产为 PM，大写）
YASHAN_USER=pm                 # 必须用业务账号 pm，勿用 sys（会查 SYS.* 报表不存在）
YASHAN_PASSWORD=<业务账号密码>

# ---- 安全：两台必须相同，≥32 字节随机串 ----
JWT_SECRET=<相同随机串>

# ---- 附件：生产统一用华为 OBS ----
APP_STORAGE_TYPE=obs
APP_STORAGE_OBS_ENDPOINT=https://obs.lhim.com
APP_STORAGE_OBS_BUCKET=pdmsbucket
APP_STORAGE_OBS_AK=<AK>
APP_STORAGE_OBS_SK=<SK>
APP_STORAGE_OBS_PREFIX=uploads      # 对象在桶内 uploads/ 前缀下，与存量结构一致

# ---- 对外端口 ----
WEB_PORT=8080
```

**第 3 步 · 校验配置**（可选但强烈建议，能提前发现 90% 的低级错误）

```bash
cd /home/lhim/pm/app
docker compose config --quiet       # 无输出即通过（有错会直接打印出来）

# 确认 .env 确实被读到（应打印出你填的值，而不是空/默认值）
docker compose config | grep -E 'IMAGE|YASHAN_USER|APP_STORAGE_TYPE'
```

> 若打印的是默认值 → `.env` 没放在 compose 同目录：必须在 `/home/lhim/pm/app/` 下。

**第 4 步 · 导入镜像**（离线，只 load 不 build）

```bash
docker load -i /home/lhim/pm/releases/pm-images-aarch64-v3.1.1.tar.gz
# 期望输出：
#   Loaded image: pm-backend:v3.1.1
#   Loaded image: pm-frontend:v3.1.1

docker images | grep pm-          # 复核两个镜像都在，且 tag 与 .env 的 IMAGE_TAG 一致
```

**第 5 步 · 启动**

```bash
cd /home/lhim/pm/app
docker compose up -d
# 期望输出：Container pm-backend Started / Container pm-frontend Started

docker compose ps
# 期望：pm-backend  STATE=Up (healthy)；pm-frontend STATE=Up
```

> 后端启动需约 30~90 秒；`health: starting` 属正常，稍等再 `ps` 一次。  
> 编排文件已设 `pull_policy: never`：若镜像没 load 成功，会立刻报 `No such image: pm-backend:v3.1.1`——这是**好事**，说明它不会去联网拉、也不会误触发构建。

**第 6 步 · 验收** → 见 §5。**A、B 两台都做完 §3 后**，再做 §5 的 A6 跨机校验。

## 4. 服务器：迭代更新（每次发版走一遍）

> 与首次部署的区别：**只需换镜像 + 改一个版本号**，`.env` 其他内容不动，编排文件通常也不动。

**第 1 步 · 导入新镜像**（两台各做）

```bash
docker load -i /home/lhim/pm/releases/pm-images-aarch64-<新版本>.tar.gz
docker images | grep pm-          # 新 tag 已存在；旧 tag 仍在（可回滚）
```

**第 2 步 · 如有编排变更则覆盖**（通常跳过）

```bash
# 仅当本次发版改过 docker-compose.deploy.yml 时才需要（发布说明会写）
scp dist/pm-release-<新版本>/docker-compose.yml lhim@pdmsappgh:/home/lhim/pm/app/
```

**第 3 步 · 切到新版本**

```bash
cd /home/lhim/pm/app
# 方式一：改 .env 里的 IMAGE_TAG 为新版本（推荐，持久生效）
vi .env                          # IMAGE_TAG=v3.1.2
docker compose up -d

# 方式二：命令行临时指定（不改 .env）
IMAGE_TAG=v3.1.2 docker compose up -d
```

**第 4 步 · 验收** → §5（至少跑 A1、A3、A4）。

**第 5 步 · 升第二台**：第一台验收通过后再升另一台（滚动升级，避免同时中断）。

**回滚**：把 `.env` 的 `IMAGE_TAG` 改回上一版本号 → `docker compose up -d`（旧镜像仍在本机，无需重新 load）。

## 5. 部署后验收（首次与每次更新后都跑）

在**服务器本机**执行：

| #  | 命令 / 操作                                         | 期望结果                                |
| -- | ----------------------------------------------- | ----------------------------------- |
| A1 | `curl http://127.0.0.1:8080/api/health`         | `{"code":0,...,"data":{"db":"up"}}` |
| A2 | 浏览器打开 `http://<服务器IP>:8080` → 登录 `admin/123456` | 正常进入首页                              |
| A3 | 打开任一项目 → 下载一个**存量**附件                           | HTTP 200 且文件大小 > 0（读 OBS 桶成功）       |
| A4 | 新上传一个附件 → 再下载                                   | 能下载且与原文件字节一致（写 OBS 成功）              |
| A5 | 删除该附件 → 再下载                                     | 提示附件不存在（`code=404`）                 |
| A6 | 两机都起来后：用 A 登录拿到的 token 访问 B 的接口                 | 200（证明两台 `JWT_SECRET` 一致）           |

带 token 的 A3/A4 命令行版本：

```bash
BASE=http://127.0.0.1:8080

TOKEN=$(curl -s -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"account":"admin","password":"123456"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# A3 下载存量附件（把 <附件id> 换成实际 id）
curl -s -o /tmp/att.bin -w "HTTP=%{http_code} size=%{size_download}\n" \
  "$BASE/api/attachments/<附件id>/download" -H "Authorization: Bearer $TOKEN"
# 期望 HTTP=200 size>0；与源文件比对：sha256sum /tmp/att.bin
```

> A3 失败（404）时：优先核对 `/home/lhim/pm/app/.env` 中 `APP_STORAGE_OBS_PREFIX=uploads` 是否与桶内实际结构一致。

## 6. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker: 'compose' is not a docker command` | compose 插件未装 / **架构不符** | §1.2 ③ 放对架构的二进制（aarch64 机必须 aarch64 版）并 `chmod +x` |
| `Cannot connect to the Docker daemon at ... docker.sock` | daemon 未启动 | `sudo systemctl enable --now docker` |
| `permission denied ... docker.sock` | 用户不在 docker 组 | `sudo usermod -aG docker lhim` → **重登 SSH** |
| `No such image: pm-backend:vX` | 镜像没 load，或 `.env` 的 `IMAGE_TAG` 与 load 的 tag 不一致 | `docker load` 后核对 `docker images \| grep pm-` 与 `.env` 的 `IMAGE_TAG` |
| `compose config` 打印的还是默认值 / 提示 `YASHAN_PASSWORD 必须设置` | `.env` 不在 compose 同目录 | 移到 `/home/lhim/pm/app/.env` |
| 提示 `failed to solve: ... context` 或试图联网构建 | 误用了仓库里带 `build:` 的编排文件 | 服务器只用发布包里的 `docker-compose.yml`（无 build 段） |
| `up -d --build` 拉取失败 | 服务器无外网 | 去掉 `--build`，走开发机构建 + `docker load` |
| `docker save` 报 `No such image` | 构建时漏了 `--load` | 重跑构建并加 `--load`（§2.3） |
| 启动报 `exec format error` | 镜像架构与机器不符 | 用 `uname -m` 复核，重新 load 对应架构包（aarch64↔aarch64） |
| 附件下载 404 | `APP_STORAGE_OBS_PREFIX` 与桶结构不符 / 对象不存在 | 核对 prefix=uploads；比对 `attachment.file_path` |
| 附件上传成功但另一台看不到 | 用了 local 存储 | 两台 `.env` 均为 `APP_STORAGE_TYPE=obs` |
| 一台登录的 token 在另一台 401 | 两机 `JWT_SECRET` 不同 | 改成完全相同的值后重启后端 |
| 后端反复重启 | 崖山连不上 / JWT_SECRET 过短 | `docker compose logs -f backend` 看栈；核对 IP/账号/密码 |
| 容器时间差 8 小时 | 时区未生效 | 编排已设 `TZ=Asia/Shanghai`，确认未被 `.env` 覆盖掉 |

**通用排查命令**（在 `/home/lhim/pm/app` 下执行，无需 `-f`）：

```bash
cd /home/lhim/pm/app
docker compose ps                # 状态
docker compose logs -f backend   # 后端日志（Ctrl+C 退出）
docker compose restart backend   # 只重启后端
docker system df                 # 磁盘占用（镜像多时清理旧 tag）
```

## 7. 版本与约定

- **服务器不存源码**：运行目录只有 `docker-compose.yml` + `.env`；代码变更通过镜像传递。
- **镜像 tag 与迭代号一致**（`v3.1.1`）；服务器用 `.env` 的 `IMAGE_TAG` 控制运行版本 → 便于多版本共存与秒级回滚。
- **`.env` 只存在于服务器本地**，永不入库、永不被发布包覆盖；新增配置项在发布说明中列出，手工追加。
- **发布物**（`dist/`、镜像 tar）不入 git，只作为文件传递。
- **推送策略**：本地提交即可，是否需要推送由你决定（AI 不主动 push）。
- **改动同步**：发版前更新 `ITERATION.md`，并同步 README / 本文档 / 方案文档。
- 服务器日常零外网依赖；若后续启用内网 Gitea，可将 §2.4 的 scp 替换为 Release 下载 + `scripts/pm-upgrade.sh`（见双机手册 §5）。
