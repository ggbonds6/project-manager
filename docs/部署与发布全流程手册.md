> **文档性质：操作手册（SOP）。** 按"初始化（首次）"与"更新（迭代发版）"两条路径组织，主体步骤可直接照做；
> 环境准备、故障排查见对应章节。运行架构 / OBS / 网关 / 运维细节以《双机ARM服务器独立部署方案.md》为准（本文不再重复原理）。
> 关联文档：`docs/双机ARM服务器独立部署方案.md`（架构与运维）、`docs/内网代码托管平台搭建-Gitea.md`（可选内网代码托管）。

## 0. 角色与机器一览（先对号入座）

| 角色 | 机器 | 架构 | 外网 | Docker | 说明 |
| --- | --- | --- | --- | --- | --- |
| **构建机 / 开发机** | Windows 开发机 | x86_64 | ✅ 有 | 需安装 Docker Desktop（见 §1.1） | 唯一能联网构建的机器；Git 仓库所在 |
| 服务器 A | `pdmsappgh`，银河麒麟 V11 | **aarch64** | ❌ 无 | daemon+cli 已装（需启动） | 登录 `lhim`，工作目录 `/home/lhim/pm` |
| 服务器 B | `ai-kingbase-gh`，银河麒麟 V11 | **aarch64** | ❌ 无（同内网） | 同上 | 登录 `lhim`，工作目录 `/home/lhim/pm` |

> **两台均为 ARM64（aarch64）**（仍以各机 `uname -m` 实查为准）→ **镜像完全通用**：开发机产一份 arm64 镜像包，两台服务器都能 `load`。
> 关键约束：**服务器不联网** → 一切构建在开发机完成，产物（镜像 tar + 运行文件）scp 上传；服务器只 `docker load` + `compose up`。

外部依赖（两台共用同一套）：崖山 YashanDB 主备（10.254.212.106/.107:1688）、华为 OBS 桶 `pdmsbucket`（附件，对象在桶内 `uploads/` 前缀下）。

## 1. 一次性准备（只做一次：开发机 + 每台服务器）

### 1.1 开发机（Windows，构建机）准备

**① 安装 Docker Desktop（Windows）**
1. 下载安装包：<https://www.docker.com/products/docker-desktop/>（Windows 版）。
2. 安装时选 **WSL2 后端**（需 Windows 10/11 已启用 WSL2；安装向导会提示，按引导启用并重启）。
3. 启动 Docker Desktop，等待右下角显示 "Engine running"。
4. 验证（在 PowerShell 或 Git Bash 执行）：

```powershell
docker --version          # 应显示 Docker version 24+ / 26+
docker compose version     # 应显示 Docker Compose version v2.x
docker buildx version      # 应显示 github.com/docker/buildx v0.x
docker run --rm hello-world   # 能打印 Hello from Docker! 即引擎正常
```

**② 启用 ARM(aarch64) 模拟（本机是 x86，构建 arm64 镜像必需；只需执行一次）**

```powershell
docker run --privileged --rm tonistiigi/binfmt --install arm64
# 验证：应能看到 linux/arm64
docker buildx ls
```

**③ 拉取本项目源码**（或使用已有本地仓库，拉到最新即可）

```powershell
git clone https://github.com/ggbonds6/project-manager.git
cd project-manager
```

> 提示：Docker Desktop 下载镜像默认走国外源，国内网络慢时可到 Settings → Docker Engine 配置镜像加速器（registry mirror），或通过公司内网代理访问。

### 1.2 服务器准备（每台各执行一次，初始化）

```bash
# ① Docker daemon 启动并设开机自启（麒麟已装 docker-cli+containerd，只需启动；
#    若 yum list docker-engine 存在而没装，先 sudo yum install -y docker-engine）
sudo systemctl enable --now docker
systemctl status docker --no-pager | head -5     # 期望 active (running)

# ② 当前用户加入 docker 组（避免每次 sudo）——然后退出 SSH 重登生效
sudo usermod -aG docker lhim
docker ps                  # 重登后应能列出（哪怕空）

# ③ 安装 docker compose v2 插件（麒麟源无该包，用官方二进制 aarch64 版）
uname -m                        # 应为 aarch64
#   下载 docker-compose-linux-aarch64（从有网机器获取后 scp 到服务器 /tmp），然后：
mkdir -p ~/.docker/cli-plugins
cp /tmp/docker-compose-linux-aarch64 ~/.docker/cli-plugins/docker-compose
chmod +x ~/.docker/cli-plugins/docker-compose
docker compose version          # 期望 Docker Compose version v2.x（报 not a docker command = 文件缺失/架构不符）

# ④ 建工作目录（releases 放镜像包；源码放 /home/lhim/pm/project-manager，见 §3 前置）
mkdir -p /home/lhim/pm/releases
```

> 常见坑：`docker compose version` 报 `'compose' is not a docker command` → 插件文件缺失或**架构与机器不符**（aarch64 机器必须放 aarch64 版二进制）。

## 2. 迭代发布全流程（每次发版走一遍）

```text
§2.1 本地开发+验证  →  §2.2 构建镜像(开发机)  →  §2.3 组装发布物
   →  §2.4 上传服务器  →  §2.5 首次部署 或 §2.6 更新部署  →  验收 §4
```

### 2.1 本地开发、测试与提交

1. 修改代码 → 本地跑通（后端 `mvn spring-boot:run`、前端 `npm run dev`；数据库连测试崖山）。
2. 提交并打版本标签（约定：迭代号，如 `v3.2.0`；`git tag v3.2.0`）。**推送由你决定**，部署用到的只是本地文件，不依赖远端。
3. 记录变更到 ITERATION.md（可让 AI 同步文档）。

### 2.2 构建镜像（开发机，Docker Desktop；两台同为 aarch64 → 产一份即可）

```bash
# 在仓库根目录执行。VER 用本次版本标签，如 v3.2.0（对应后面 IMAGE_TAG）
cd project-manager
VER=v3.2.0
mkdir -p dist

# 用 buildx 产出 ARM64(aarch64) 镜像（本机为 x86_64，靠 QEMU 模拟构建）
docker buildx build --platform linux/arm64 -t pm-backend:${VER}  -f deploy/docker/Dockerfile.backend  .
docker buildx build --platform linux/arm64 -t pm-frontend:${VER} -f deploy/docker/Dockerfile.frontend .

# 导出为单文件（两台服务器通用）
docker save pm-backend:${VER} pm-frontend:${VER} | gzip > dist/pm-images-arm64-${VER}.tar.gz
```

> - 首次构建会下载基础镜像与 Maven/npm 依赖，ARM 模拟构建较慢，属正常；构建机必须能联网。
> - 后续迭代有缓存会快很多。
> - 产物目录 `dist/`（已在 .gitignore，不入库）。

### 2.3 组装发布物

| 文件 | 来源 | 说明 |
| --- | --- | --- |
| `pm-images-arm64-<VER>.tar.gz` | §2.2 产物 | arm64 镜像包，两台通用（必需） |
| `docker-compose.yml` | `deploy/docker/docker-compose.yml` | 若本版本有改动需随包上传（含 `image:` 字段，供离线 load 直用） |
| `.env.example` | `deploy/docker/.env.example` | 首次生成 `.env` 用（之后更新不覆盖 .env） |

> 服务器上运行目录 = **源码目录 `/home/lhim/pm/project-manager`**（部署用其 `deploy/docker/docker-compose.yml`，`.env` 放仓库根）。
> 首次需把整个源码传上去（见 §3 前置）；后续更新只需传镜像包 +（如有）变更的 compose 文件。

### 2.4 上传到服务器（开发机执行，内网可达）

```bash
# 镜像包 → 两台（同一份 arm64）
scp dist/pm-images-arm64-${VER}.tar.gz lhim@pdmsappgh:/home/lhim/pm/releases/
scp dist/pm-images-arm64-${VER}.tar.gz lhim@ai-kingbase-gh:/home/lhim/pm/releases/

# 本版本若有更新的部署文件（如 docker-compose.yml/.env.example），覆盖到两台服务器源码对应位置：
scp deploy/docker/docker-compose.yml lhim@pdmsappgh:/home/lhim/pm/project-manager/deploy/docker/
scp deploy/docker/docker-compose.yml lhim@ai-kingbase-gh:/home/lhim/pm/project-manager/deploy/docker/
```

## 3. 首次部署（每台只做一次；前提 §1.2 已完成）

> 前置：**首次需把源码传到服务器**（无外网，用 scp/拷贝，不用 git pull）。
> 开发机：`scp -r project-manager lhim@pdmsappgh:/home/lhim/pm/`（或先 tar 再解压，见双机手册 §3.1 ③）。

```bash
# 服务器上执行（A、B 各一次）
cd /home/lhim/pm

# 1) 准备 .env（首次生成；之后更新不覆盖）
cd /home/lhim/pm/project-manager
cp deploy/docker/.env.example ./.env && vi ./.env    # 见下方字段表

# 2) 导入镜像并启动（离线：只 load，不 build）
docker load -i /home/lhim/pm/releases/pm-images-arm64-${VER}.tar.gz
docker compose -f deploy/docker/docker-compose.yml up -d      # 不加 --build！
```

**.env 字段（两台一致；OBS/JWT/崖山两机必须相同）**：

```bash
# ---- 镜像版本：与 docker load 的 tag 一致（回滚时改这里指旧版本）----
IMAGE_TAG=v3.2.0

# ---- 崖山数据库 ----
YASHAN_MASTER_IP=10.254.212.106
YASHAN_STANDBY_IP=10.254.212.107
YASHAN_DB=project_manager
YASHAN_USER=pm
YASHAN_PASSWORD=<业务账号密码>

# ---- 安全（两机相同）----
JWT_SECRET=<相同随机串，≥32字节>

# ---- 附件：华为 OBS ----
APP_STORAGE_TYPE=obs
APP_STORAGE_OBS_ENDPOINT=https://obs.lhim.com
APP_STORAGE_OBS_BUCKET=pdmsbucket
APP_STORAGE_OBS_AK=<ak>
APP_STORAGE_OBS_SK=<sk>
APP_STORAGE_OBS_PREFIX=uploads

# ---- 对外端口 ----
WEB_PORT=8080
```

## 4. 部署后验收（首次与每次更新后都跑）

| # | 检查 | 期望 |
| --- | --- | --- |
| A1 | `curl http://127.0.0.1:8080/api/health` | `{"code":0,...,"db":"up"}` |
| A2 | 网页登录 admin/123456 | 正常进入 |
| A3 | 下载一个存量附件（obs 读桶） | HTTP 200 且 size>0（若 404：检查 `.env` 的 `APP_STORAGE_OBS_PREFIX=uploads` 与桶内结构） |
| A4 | 新上传一个附件 → 能下载 | 字节一致 |
| A5 | 删除后下载 | body `code=404` |
| A6 | 两台都起后：A 签发的 token 访问 B | 200（JWT_SECRET 一致） |

> 具体 curl 命令见《双机ARM服务器独立部署方案.md》§3.5。更新部署通常至少跑 A1、A3、A4。

## 5. 后续迭代更新 / 再部署（增量，每次发版）

```text
开发机：改代码 → 本地验证 → §2.2 构建(新 VER) → §2.3 组装
   → §2.4 scp（镜像 tar + 变更过的文件，通常只需 docker-compose.yml）
服务器（每台）：
   docker load -i /home/lhim/pm/releases/pm-images-arm64-<新VER>.tar.gz   # 导入新镜像（旧镜像仍在，可回滚）
   # 若 compose/.env 字段有变更：先覆盖源码里的 deploy/docker/docker-compose.yml；.env 按需手改（不要整体覆盖）
   cd /home/lhim/pm/project-manager
   IMAGE_TAG=<新VER> docker compose -f deploy/docker/docker-compose.yml up -d
   # IMAGE_TAG 也可写入 .env（更持久）；回滚时改回旧版本号
   → 跑 §4 验收
```

- **数据库/附件不受影响**：数据在崖山库、附件在 OBS，重建容器不丢数据（附件卷仅为过渡 local 用）。
- **`.env` 原则**：只在首次生成；更新时**不要用 .env.example 覆盖**，新增配置项按发布说明手工追加。
- **滚动两台顺序**：先升一台 → 验收 → 再升第二台；网关健康检查自动摘除未就绪节点。
- **回滚**：上一版镜像还在本机镜像库 → `.env` 把 `IMAGE_TAG` 改回旧版本（或 `docker load` 旧包）→ `docker compose up -d`。
- **升级/安装脚本**：也可用 `scripts/pm-upgrade.sh <镜像tar> <运行目录>` 替代手工 load+up（脚本负责 load、compose 校验、up）。

## 6. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker: 'compose' is not a docker command` | compose 插件未装或**架构不符** | §1.2③ 重新放对架构的二进制并 `chmod +x` |
| `Cannot connect to the Docker daemon at ... docker.sock` | daemon 未启动 | `sudo systemctl enable --now docker` |
| `permission denied ... docker.sock` | 用户不在 docker 组 | `sudo usermod -aG docker lhim` + 重登 |
| `up -d --build` 拉取镜像/依赖失败 | 服务器无外网 | 不要 `--build`，走 load 模式（§3） |
| 附件下载 404 | `APP_STORAGE_OBS_PREFIX` 与桶结构不符 / 桶内无此对象 | 核对 `.env` prefix=uploads 与 `file_path`；见双机手册 §6 |
| `docker compose version` 报 not a command | 该机插件文件缺失或架构与该机不符 | 按该机 `uname -m` 放对应架构二进制（当前两台均为 aarch64） |
| 镜像 tar 在另一台 load 后启动失败(exec format) | tar 架构与该机不符 | 用对应架构的 tar（aarch64↔aarch64、x86_64↔x86_64） |

## 7. 文件与版本约定

- 镜像 tag 建议与迭代号一致（`v3.2.0`），`IMAGE_TAG` 由服务器 `.env` 控制 → 便于多版本共存与回滚。
- `.env`、OBS/数据库凭证**一律不入 git**；仓库内 `.env.example` 只含占位。
- 每次发版前在 ITERATION.md 记录并同步相关文档（本仓库维护约定）。
- 构建产物（`dist/`、镜像 tar）不入 git，只作为发布物传递。
