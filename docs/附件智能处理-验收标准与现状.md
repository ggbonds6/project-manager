## 1. 验收标准（判定标准，不是操作步骤）

| 编号 | 场景 | 判定标准（通过线） |
| --- | --- | --- |
| **A1** | 附件构成统计 | 得出明确的**扫描件占比**与 **OFD 占比**数字；列出所有 >50MB 文件及页数 |
| **A2** | 电子版文本提取 | 提取成功率 **≥95%**；抽查 10 份中 **≥9 份**文本可直接用于后续处理（文字连贯、无乱码、表格数字可用） |
| **A3** | OCR 关键字段 | 正文型正确率 **≥95%**、表格型 **≥85%**、证件型 **≥90%**；**金额/数字类错误率 ≤1%（最关键指标）**；记录单页耗时 |
| **A4** | 切片方案 | **结构化切片自包含率 ≥90%**（定长切片作基线对照）；确定合同类按条款号的切片规则 |
| **A5** | OFD 提取可行性 | 至少存在 **1 条可用路径**（含"转图片 → OCR"保底），并记录其准确率与耗时 |
| **B1** | 单文件字段抽取 | 强特征字段（金额/日期/编号）**≥95%**；弱特征字段（摘要/结论/人名）**≥80%**；**幻觉率 ≤2%** |
| **B2** | 证据回溯 | 证据**字面存在于原文**的比例 **≥95%**（不是模型改写）；人工抽查 10 条，证据与字段值对应关系正确 **≥90%** |
| **B3** | 批量抽取 | 与 B1 小样本准确率偏差 **≤10%**；输出**分类别**准确率表 |
| **C1** | 短文档整篇问答（<10 页） | 答案正确率 **≥85%**；答案带原文引用且引用可核验 |
| **C2** | 大文档检索问答 | **支付节点抽全率 ≥90%**、**金额正确率 ≥90%**、**引用可核验率 ≥90%**；记录单份大合同全流程耗时（OCR+切片+向量化） |
| **C3** | 跨文档聚合问答 | 聚合正确率 **≥85%**；**精确金额汇总走 SQL，不走模型计算** |

> 上表阈值为**建议值**；审计场景建议**宁高勿低、先小范围用**。

**决策阈值（由 A 类结果直接决定路线）**

| 实测情形 | 下一步 |
| --- | --- |
| 扫描件占比 **>50%** | **OCR 必须先做** |
| OFD 占比 **>20%** | 先解决 OFD 提取（独立风险） |
| 金额数字错误率 **>1%** | ① 提高 DPI ② 换 OCR 引擎 ③ 关键金额**强制人工确认** |
| 精确统计（多少笔/多少钱） | **走 SQL**，相似度算不出来 |

## 2. 当前实现与实测数字（2026-09-20 · 网关 `10.254.208.35:8090`）

| 项 | 实测值 |
| --- | --- |
| 实现 | Java `ai-backend`（Spring Boot 3.3.5 / Java 17），独立构建、独立发版、默认端口 **8100**；对话 / 平台 OCR / 向量化 / 重排**全部在内网平台网关**，共用**同一把 sk**，服务侧只做 HTTP 调用 |
| 平台 OCR（扫描件 1 页） | **≈1.3~1.7s**：首次 `engine=platform` 墙钟 **1.29s**（elapsed 1.29s，Python 基线 1.56s）；复跑 elapsed **1.46s** / 墙钟 **1.66s** |
| 抽取 `/analyze` | **≈8.0~8.7s**：首次 **8.73s**、tokens **1375+779**；复跑 **7.98s**、tokens **1374+766**；`llm.ok=true`，带 `[P1]` 来源与置信度 |
| 上传任务 | `QUEUED→DONE`、percent 100：首次 **1.47s**；复跑 **1.28s**（墙钟约 1.5s） |
| 问答 `/chat` | 首次 **10.27s**，轨迹 `search_documents×2 → read_page`；复跑 **9.93s**，轨迹 `search_documents×2`（`rounds=2`、`stopped_reason=done`）；金额正确且主动存疑、未找到项如实说明 |
| PDF 文本层抽取 | 与 PyMuPDF **逐字节一致**：电子版 **182 字** / 扫描件 **0 字**（Java 用 PDFBox 3） |
| Embedding | **固定 4096 维**（不传 `dimensions`，平台不支持 MRL 降维）；余弦 **0.3245** 与 Python 基线**逐位一致**；语义判别 0.7605 > 0.2133（复跑换语料 0.7016 > 0.2491） |
| Reranker 精排 | **0.9903 > 0.0278 > 0.0014**、首位命中（复跑 0.2672 > 0.1178 > 0.1005，首位命中） |
| 一致性验证 | 确定性校验 `Checks` 与 Python **35 个用例逐字段差分一致**；提示词 **11 项 SHA-256 比对零差异** |
| 质量门 | **`mvn test` 81 用例全绿**（Checks 18 / Tools 22 / PlatformOcr 11 / Retrieval 17 / VecPayload 5 / PdfReader 8）；测试**纯离线**，不连平台 |
| 已知限制（照实） | 平台不返回逐页置信度（客户端 `confidence` 恒 `null`）；表格块未按列还原为结构化表；文本未做全角/半角归一化 |

> ⚠️ 读法：同一输入同模型的项（维度、余弦 0.3245）可要求逐位一致；**换了语料的相似度/排序分数不可逐位比**，它们只证明"模型在算语义、精排在排序"，**不能当阈值卡**。

## 3. 怎么自测（当前唯一入口）

```bash
# 质量门（纯离线：不连平台、不调模型、不跑 OCR，断网可跑）
cd ai-backend && mvn -B test                      # 81 用例；等价脚本 bash ai-backend/scripts/check.sh

# 端到端验收（需能访问平台网关；会在 8101 起服务，逐项打印结果并与基线对比）
pwsh -File ai-backend/scripts/verify-e2e.ps1      # 在仓库根执行
```

`verify-e2e.ps1` 覆盖：自检 → 平台 OCR → 抽取 → 上传任务 → 问答，并把 Python 基线一并打印供对比。
不带 Docker 的起服务方式：`java -jar target/pm-ai-backend-1.0.0-SNAPSHOT.jar --server.port=8101`。

## 4. 已知未完成项（如实列出）

| 未完成 | 现状 |
| --- | --- |
| **OFD 提取** | **未实现**（Python 版与 Java 版都没有）。保底路径：OFD 转图片 → 走平台 OCR |
| **附件内容哈希去重** | 无。同一份文件重复上传会**各存一份**（实测文档库出现两份内容相同的《中标通知书》）；`dedup_key = {attachment_id}:{content_hash}:{parser_version}` 仅设计未落地 |
| **评测集** | 无。**召回@k / 引用准确率 / 数字幻觉率三个基线都没有数字**，故检索调参只能凭感觉（计划：30~50 附件 + 100~200 条 QA） |
| **OpenSearch** | 正式选型，**集群未部署**；`VEC_BACKEND=opensearch` 适配层在线路由接通中，当前配了会**显式报错**（不静默退回 local）；过渡期用进程内余弦 + `work/vectors/` 缓存 |
| **文档库能力** | 无**搜索 / 引擎筛选 / 分页**（文档一多才用得下去） |
| **检索层剩余项（P2）** | RRF 打分融合、元数据/权限过滤、父块上卷均未做 |
| 其他 | 文本归一化未做（已知漏检：`7,780,000.00` 与 `7780000` 不算"写法混用"）；表格按列还原未做（平台已返回 bbox） |

## 5. 保留的决策依据（为什么这么设计）

| 决策 | 依据 |
| --- | --- |
| **OCR 只走平台，不做本地兜底** | 同一页真实合同：本地引擎金额**一个都没读到**，平台连「柒佰柒拾捌万元整」都完整。**给出低质量结果比明确报错更危险** —— 故平台不可达时**直接失败并列出失败页**，不降级 |
| **按文件大小分区处理** | 小（电子版 <10 页）：整篇喂模型，不切片不建向量；中（10~50 页）：结构化切片 + 向量检索；大（扫描件 100MB+）：OCR + 按条款切片 + 异步预处理（大合同 OCR 可能 10~25 分钟/份，**必须入库时异步完成**） |
| **确定性校验由代码算，不靠模型自觉** | 金额大小写互校"同句配对"、比例合计按段落切分容差 ±1、答案数字可溯源；模型自评置信度只用于排复核优先级，**不能替代人工核对** |
| **证据回溯是审计刚需** | 不可核验的结论在审计场景等于没有结论；喂模型的原文**按页组织**（`[P2]` 可溯源），页码是来源标注的前提 |
| 模型不塞进现有应用服务器 | 应用机为 ARM64 且无 GPU；模型/OCR/向量化都在平台网关，由服务侧 HTTP 调用 |
